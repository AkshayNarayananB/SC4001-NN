# DeCo: dynamic correction decoding from preceding layers

**Paper:** Wang et al., *MLLM Can See? Dynamic Correction Decoding for Hallucination Mitigation*,
ICLR 2025 (arXiv 2410.11779). Official code: https://github.com/zjunlp/DeCo. `DeCo/deco.py` ports
its `deco_greedy_search`, and `DeCo/tests` checks the port against a line-by-line copy of the
official logic on random inputs.

## Idea

The paper found that the model often *does* recognise the object in its middle layers, but the
language prior in the final layers overrides it. At each decoding step DeCo:

1. Takes the final layer's candidate tokens C: the top-p (0.9) prefix of its distribution, at most top-k (20) tokens.
2. Reads out every layer from 20 to 28 with the final norm and the LM head.
3. Picks the **anchor** layer: the one that gives the highest probability to any token in C. p_max is that probability.
4. Decodes from `final_logits + α · p_max · anchor_logits`, restricted to C (α = 0.6).

It needs one forward pass and no second image.

**Why it fits our problem.** Degradation pushes LLaVA's final answer towards "no" and blunts its
discrimination (Stage 2). If the evidence still survives in the middle layers of degraded images,
DeCo can recover it. That would mean genuinely better discrimination (AUROC), not a threshold shift.

**How it differs from the other fixes.**
- **#1 (zeroed visual KV-cache), #2 (shuffled positional encodings), VCD and model_fix_2:** there is no second pass and nothing is subtracted.
- **Fix B (DAE):** the image is not restored.
- **RITUAL:** no extra views. DeCo only re-reads the model's own internal layers.

## Our protocol

- LLaVA-1.5-7B, POPE MSCOCO (3 splits × 3000 questions), clean + blur s1–4 + noise s1–4.
- Same prompt and images as Stages 0–2. The final layer therefore reproduces the Stage 2 baseline, which is checked in the sanity section.
- Greedy decoding, as in the official POPE script. The exact first-token decision is recorded for several α values.
- The README reports:
  - **DeCo as published:** α = 0.6, layers 20–28. No tuning.
  - **DeCo with α chosen on 100 DEV images:** results on the 400 TEST images.
  - **A layer-wise analysis:** the AUROC of every layer's own Yes–No margin under each degradation, which tests DeCo's premise on degraded inputs directly.
- Scored like every Phase 2 fix (`fix_eval/common.py`): AUROC vs baseline and VCD, F1 vs the
  matched-threshold baseline, 95% paired-bootstrap CIs.

## Run

```bash
# ASPIRE, from ~/SC4001-NN
qsub -J 4-8:4 -v LIMIT=30 DeCo/run_deco.pbs    # smoke: blur s4 + noise s4, 30 q/split
qsub DeCo/run_deco.pbs                         # full: 9 conditions
python -m DeCo.analyze                         # fills in the Results section below

python -m pytest DeCo/tests -q                 # local CPU tests
```

Raw records: `$VCD_OUTPUT_ROOT/deco_<kind>_s<level>/<split>.jsonl`.

## Deviations from the official code

- The prompt keeps the Stage 0–2 suffix "Please answer this question with one word." The official POPE script comments it out. We keep it so the final layer equals our Stage 2 baseline.
- The official `pope_llava.py` passes `args.aplha` (a typo, which would crash). We use the intended `alpha`.
